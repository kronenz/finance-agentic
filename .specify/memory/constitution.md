# AI 기반 암호화폐 자동화 거래 시스템 Constitution

## Core Principles

### I. 적응형 이중 패러다임 프레임워크 (NON-NEGOTIABLE)
시스템은 시장의 두 가지 주요 국면(추세 국면과 평균회귀 국면)을 자동으로 식별하고, 각 국면에 최적화된 상반된 거래 패러다임을 동적으로 전환하여 적용해야 한다. 정적 전략은 금지되며, 모든 거래 로직은 현재 시장 국면에 따라 적응적으로 작동해야 한다.

### II. AI 에이전트 협력 체계
시스템은 중앙 메타-컨트롤러와 전문화된 하위 에이전트들로 구성된 협력 체계를 유지해야 한다. 각 에이전트는 명확한 역할과 책임을 가지며, 실시간 통신을 통해 의사결정을 조율해야 한다. 인간 관리자의 개입 없이도 자율적으로 운영되어야 한다.

### III. 거래량 기반 시장 심리 분석 (NON-NEGOTIABLE)
모든 거래 결정은 VWAP(거래량 가중 평균 가격)와 거래량 프로파일 분석을 기반으로 해야 한다. 단순한 가격 움직임이 아닌, 시장 참여자들의 실질적인 평균 단가와 가치 합의 영역을 파악하여 의사결정에 반영해야 한다.

### IV. 다층적 리스크 관리
개별 거래, 포트폴리오, 시스템 레벨의 3단계 리스크 관리 체계를 유지해야 한다. 각 레벨에서 독립적인 리스크 한도를 설정하고, 연쇄 청산(Liquidation Cascade) 위험을 실시간으로 모니터링하여 선제적으로 대응해야 한다.

### V. 자가 학습 및 진화 (NON-NEGOTIABLE)
시스템은 강화학습과 유전 알고리즘을 통해 지속적으로 학습하고 진화해야 한다. 과거 성과를 분석하여 전략을 개선하고, 새로운 시장 환경에 적응할 수 있는 능력을 유지해야 한다.

### VI. Spec Driven Development
모든 기능 개발은 명세서 작성부터 시작해야 한다. 명세서 검토 → 개발 → 검증 → 배포의 6단계 워크플로우를 엄격히 준수해야 하며, 각 단계별 품질 게이트를 통과해야 한다.

## 기술 스택 및 아키텍처 제약사항

### 백엔드 아키텍처
- **언어**: Python 3.9+ (AI/ML 라이브러리 호환성)
- **프레임워크**: FastAPI (고성능 비동기 처리)
- **데이터베이스**: PostgreSQL (트랜잭션 무결성) + Redis (실시간 캐싱)
- **AI/ML**: scikit-learn, pandas, numpy (데이터 분석), 강화학습 프레임워크

### 프론트엔드 아키텍처
- **프레임워크**: React 18+ with TypeScript (타입 안전성)
- **상태관리**: Redux Toolkit (복잡한 상태 관리)
- **스타일링**: Apple 홈페이지 스타일 디자인 시스템
- **차트**: 실시간 거래량 프로파일 및 VWAP 시각화

### AI 에이전트 통신
- **프로토콜**: RESTful API + WebSocket (실시간 통신)
- **메시지 형식**: JSON (구조화된 데이터 교환)
- **인증**: JWT 기반 (보안성)

## 개발 워크플로우 및 품질 관리

### 필수 개발 프로세스
1. **명세서 작성**: 기능 요구사항을 명확히 정의
2. **AI 에이전트 검토**: 해당 역할의 AI 에이전트가 명세서 검토
3. **개발**: TDD 방식으로 테스트 코드 우선 작성
4. **통합 테스트**: 다중 에이전트 환경에서 테스트
5. **스테이징 배포**: stage 브랜치에서 검증
6. **프로덕션 배포**: prod 브랜치로 승인된 코드만 배포

### 품질 기준
- **테스트 커버리지**: 90% 이상 (핵심 거래 로직 100%)
- **성능**: 평균 응답시간 100ms 이하
- **가용성**: 99.9% 이상 (금융 시스템 표준)
- **보안**: 모든 API 엔드포인트 인증 필수

## Governance

### 헌법 우선순위
본 헌법은 모든 개발 가이드라인, 코딩 표준, 아키텍처 결정보다 우선한다. 헌법과 충돌하는 모든 규칙은 무효화된다.

### 수정 절차
1. **제안**: 명확한 수정 사유와 영향도 분석 제시
2. **검토**: 최소 3명의 AI 에이전트 검토 필요
3. **승인**: 인간 관리자 최종 승인
4. **이행**: 모든 의존 템플릿 및 가이드라인 동기화
5. **문서화**: 변경 사항을 모든 관련 문서에 반영

### 준수 검증
- 모든 Pull Request는 헌법 준수 여부를 자동 검증
- 복잡성 증가 시 반드시 정당성 입증 필요
- 런타임 개발 가이드는 `docs/GETTING_STARTED.md` 참조
