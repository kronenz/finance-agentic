# Backtesting and A/B Testing Strategy

## 1. 개요

본 문서는 개발된 ML 모델과 거래 전략의 과거 성과를 검증하고, 실거래 적용 전 신뢰도를 확보하기 위한 백테스팅 및 A/B 테스팅 전략을 정의한다.

## 2. 백테스팅 (Backtesting)

### 2.1. 백테스팅 엔진

- **프레임워크**: `backtrader`, `Zipline`과 같은 전문 프레임워크 또는 자체 개발 엔진 사용을 고려한다.
- **주요 고려사항**:
    - **Look-ahead Bias (미래 데이터 참조 오류)**: 테스트 시점에 알 수 없는 미래의 데이터를 사용하는 오류를 철저히 배제한다.
    - **Survivorship Bias (생존 편향)**: 상장 폐지된 종목 등을 데이터에서 임의로 제외하지 않고, 실제 시장 상황을 그대로 반영한다.
    - **Transaction Costs (거래 비용)**: 수수료, 슬리피지(Slippage) 등 실제 거래에서 발생하는 비용을 현실적으로 반영한다.

### 2.2. 데이터 분할 전략

- **Walk-Forward Validation (전진 분석)**: 시계열 데이터의 순서를 유지하며, 과거 데이터로 모델을 학습하고 바로 다음 기간의 데이터로 검증하는 방식을 반복한다. 이는 실제 시장에서 전략을 운용하는 방식을 가장 잘 모방한다.
    - **Training Set**: 특정 기간의 데이터로 모델을 학습시킨다.
    - **Validation Set**: 학습 직후 기간의 데이터로 모델 성능을 검증하고 하이퍼파라미터를 튜닝한다.
    - **Test Set**: 전체 Walk-Forward 과정이 끝난 후, 한 번도 사용되지 않은 미래 데이터로 최종 성능을 평가한다.

## 3. A/B 테스팅

### 3.1. 목적

- 기존에 운영 중인 전략(Champion)과 새로운 전략(Challenger)의 성과를 실시간 또는 모의 환경에서 비교하여, 더 나은 전략을 객관적인 데이터에 기반해 선택한다.

### 3.2. 방법론

- **Paper Trading (모의 투자)**:
    - 실시간 시장 데이터를 이용하되, 실제 자금을 투입하지 않고 가상으로 거래를 실행한다.
    - Champion 전략과 Challenger 전략을 동시에 실행하여 성과를 비교한다.
- **Live Trading with Limited Capital (소액 실거래)**:
    - Paper Trading에서 검증된 Challenger 전략을 소액의 실제 자금으로 운용한다.
    - 실거래 환경에서 발생할 수 있는 예상치 못한 문제(API 지연, 시스템 오류 등)를 파악하고 안정성을 최종 점검한다.

### 3.3. 평가

- 일정 기간(최소 1개월 이상) 동안 두 전략을 운영한 후, **금융 성과 평가 지표(PnL, Sharpe Ratio, MDD 등)**를 비교하여 어느 전략이 더 우수한지 통계적으로 평가한다.

## 4. 성과 리포팅

- **자동화**: 백테스팅 및 A/B 테스팅 실행 후, 결과 리포트를 자동으로 생성하는 시스템을 구축한다.
- **리포트 내용**:
    - **Equity Curve (자산 곡선)**: 시간에 따른 자산 변화를 시각화.
    - **Drawdown Plot**: 자산의 낙폭 변화를 시각화.
    - **Trade Log**: 모든 거래의 진입/청산 시점, 가격, 수량, 손익 등을 기록.
    - **Summary Statistics**: PnL, MDD, Sharpe Ratio 등 핵심 평가 지표 요약.

## 5. 백테스팅 구현 세부사항

### 5.1. 데이터 준비

- **시계열 데이터 정렬**: 시간 순서대로 정렬하여 미래 데이터 참조 방지
- **데이터 품질 검증**: 결측치, 이상치, 중복 데이터 처리
- **데이터 분할**: 훈련(70%), 검증(15%), 테스트(15%) 비율로 분할

### 5.2. 거래 시뮬레이션

- **주문 실행**: 실제 거래소 API와 유사한 주문 처리 로직
- **수수료 계산**: 거래소별 수수료 구조 반영
- **슬리피지 모델링**: 시장 충격도에 따른 슬리피지 계산
- **유동성 제약**: 대량 주문 시 시장 충격 고려

### 5.3. 성과 측정

- **수익률 계산**: 일간, 주간, 월간 수익률 계산
- **위험 지표**: 변동성, VaR, 최대 드로우다운 계산
- **거래 통계**: 거래 횟수, 승률, 평균 수익/손실
- **벤치마크 비교**: 시장 지수 대비 초과 수익률

## 6. A/B 테스팅 구현 세부사항

### 6.1. 실험 설계

- **랜덤화**: 거래를 랜덤하게 두 전략에 할당
- **통제 변수**: 동일한 시장 조건에서 테스트
- **표본 크기**: 통계적 유의성 확보를 위한 충분한 표본
- **실험 기간**: 최소 1개월, 권장 3개월

### 6.2. 성과 비교

- **통계적 검정**: t-test, Mann-Whitney U test 등
- **효과 크기**: Cohen's d, Hedge's g 등
- **신뢰구간**: 95% 신뢰구간으로 효과 크기 추정
- **유의수준**: p < 0.05로 통계적 유의성 판단

### 6.3. 편향 방지

- **선택 편향**: 거래 선택 과정의 편향 제거
- **시간 편향**: 특정 시기 데이터에 대한 편향 제거
- **확인 편향**: 결과에 맞춰 가설을 수정하는 편향 방지

## 7. 모니터링 및 알림

### 7.1. 실시간 모니터링

- **성과 지표**: 실시간 PnL, 드로우다운, 승률 추적
- **시스템 상태**: API 연결, 데이터 수신, 모델 실행 상태
- **알림 설정**: 임계값 초과 시 자동 알림

### 7.2. 정기 리포팅

- **일간 리포트**: 일일 성과 요약
- **주간 리포트**: 주간 성과 분석 및 트렌드
- **월간 리포트**: 월간 성과 종합 분석

## 8. 위험 관리

### 8.1. 백테스팅 위험

- **과최적화**: 과거 데이터에 과도하게 맞춘 모델
- **데이터 누수**: 미래 정보가 과거 예측에 사용되는 경우
- **시장 변화**: 과거 패턴이 미래에도 유지되지 않는 경우

### 8.2. A/B 테스팅 위험

- **실험 중단**: 중간에 실험을 중단하여 결과 왜곡
- **선택 편향**: 특정 조건의 거래만 선택하는 편향
- **통계적 오류**: 잘못된 통계 검정으로 인한 잘못된 결론

## 9. 자동화 및 도구

### 9.1. 백테스팅 자동화

- **스케줄링**: 정기적인 백테스팅 실행
- **결과 저장**: 성과 데이터 자동 저장 및 버전 관리
- **리포트 생성**: 자동화된 성과 리포트 생성

### 9.2. A/B 테스팅 자동화

- **실험 관리**: 실험 설정, 실행, 모니터링 자동화
- **성과 추적**: 실시간 성과 지표 추적
- **결과 분석**: 자동화된 통계 분석 및 리포트

## 10. 구현 로드맵

### 10.1. Phase 1: 기본 백테스팅 (1주)
- 백테스팅 엔진 구축
- 기본 성과 지표 구현
- Walk-Forward Validation 구현

### 10.2. Phase 2: A/B 테스팅 (1주)
- A/B 테스팅 프레임워크 구축
- 통계적 검정 구현
- 실시간 모니터링 시스템 구축

### 10.3. Phase 3: 고도화 (1주)
- 고급 성과 지표 추가
- 자동화 시스템 구축
- 대시보드 및 알림 시스템 구축
