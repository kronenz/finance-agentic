# AI 에이전트 협력 체계 설계

## 1. 개요

본 문서는 `concept.md`에서 제시된 'Agentic AI'의 역할을 구체화하고, 다수의 AI 에이전트가 효율적으로 협력하여 시장 분석, 전략 결정, 거래 실행, 리스크 관리 등 복합적인 작업을 수행하기 위한 협력 체계(Collaboration Framework)를 설계한다. 이 시스템은 중앙 집중형 제어와 분산형 전문화를 결합한 하이브리드 모델을 채택한다.

## 2. 아키텍처: 메타-컨트롤러와 전문 에이전트

시스템은 '메타-컨트롤러(Meta-Controller)'라는 중앙 AI 에이전트와 각자의 전문 영역을 담당하는 다수의 '하위 에이전트(Sub-Agents)'로 구성된다.

![Agent Architecture](https://i.imgur.com/eZ5Qv9a.png)

### 2.1. 메타-컨트롤러 (Meta-Controller)

-   **역할**: 시스템의 '두뇌'이자 최종 의사결정권자. 모든 하위 에이전트로부터 정보를 보고받고, 이를 종합하여 전체 시스템의 목표(수익 극대화, 리스크 최소화)에 부합하는 '메타 전략'을 수립하고 실행을 지시한다.
-   **핵심 기능**:
    -   **전략 오케스트레이션**: '시장 국면 분석 에이전트'로부터 현재 시장 국면을 보고받고, 이에 가장 적합한 거래 전략(추세추종, 평균회귀 등)을 활성화하도록 '전략 분석 에이전트'에 지시한다.
    -   **리스크 총괄 관리**: '리스크 관리 에이전트'로부터 포트폴리오 전체의 위험 수준을 보고받고, 시장 상황에 따라 허용 레버리지, 전체 노출 한도 등 시스템 레벨의 리스크 파라미터를 동적으로 조절한다.
    -   **자원 할당**: 각 하위 에이전트의 연산 및 데이터 접근 권한을 관리하고 조율한다.
    -   **최종 거래 승인**: '거래 실행 에이전트'가 제안한 최종 거래 주문(진입 가격, 수량, 손절매 등)을 검토하고 최종적으로 승인하거나 거부한다.

### 2.2. 전문화된 하위 에이전트 (Specialized Sub-Agents)

각 하위 에이전트는 특정 임무에 고도로 전문화되어 있으며, 메타-컨트롤러의 지시에 따라 독립적으로 작업을 수행하고 결과를 보고한다.

1.  **데이터 수집 에이전트 (Data Collection Agent)**
    -   **임무**: 모든 필요한 데이터 스트림(거래소 API, 온체인 데이터 제공자, 소셜 미디어 피드 등)에 연결하여 원시 데이터를 수집하고, 정제하여 중앙 데이터베이스에 저장한다.
    -   **산출물**: 정규화된 시계열 데이터, 이벤트 로그.

2.  **시장 국면 분석 에이전트 (Market Regime Analysis Agent)**
    -   **임무**: `시장 국면 분석 시스템 설계` 문서에 따라, 현재 시장의 국면을 실시간으로 분석하고 분류한다.
    -   **산출물**: 현재 시장 국면 레이블 (예: `TREND_UP_HIGH_VOL`), 신뢰도 점수.

3.  **전략 분석 에이전트 (Strategy Analysis Agent)**
    -   **임무**: 메타-컨트롤러가 지정한 시장 국면에 따라, 활성화된 전략(예: 추세추종)의 구체적인 거래 신호를 생성한다. (예: '슈퍼트렌드 상향 돌파, 매수 신호 발생')
    -   **산출물**: 거래 신호(Signal), 추천 진입/청산 가격, 신호 강도.

4.  **거래 실행 에이전트 (Trade Execution Agent)**
    -   **임무**: '전략 분석 에이전트'로부터 거래 신호를 받아, 최적의 거래 주문(지정가, 시장가, 분할 주문 등)을 설계하고, '리스크 관리 에이전트'의 포지션 크기 계산 결과를 반영하여 최종 주문 계획을 수립한다.
    -   **산출물**: 메타-컨트롤러에 제출할 거래 주문 제안(Trade Order Proposal).

5.  **리스크 관리 에이전트 (Risk Management Agent)**
    -   **임무**: 개별 거래의 리스크(포지션 크기, 손절매 위치)와 포트폴리오 전체의 리스크(최대 손실폭, VaR)를 계산하고 모니터링한다.
    -   **산출물**: 추천 포지션 크기, 필수 손절매 가격, 현재 포트폴리오 리스크 수준 보고.

## 3. 에이전트 간 통신 프로토콜

에이전트 간의 모든 통신은 표준화된 메시지 큐(Message Queue, 예: RabbitMQ, Kafka)를 통해 비동기적으로 이루어진다. 메시지 형식은 JSON 또는 Protobuf를 사용한다.

-   **메시지 구조 예시**:
    ```json
    {
      "message_id": "uuid-1234-abcd-5678",
      "timestamp": "2025-09-25T10:00:00Z",
      "source_agent": "Market_Regime_Agent",
      "destination_agent": "Meta_Controller",
      "event_type": "REGIME_UPDATE",
      "payload": {
        "regime": "TREND_UP_HIGH_VOL",
        "confidence": 0.85,
        "indicators": {
          "adx": 35.2,
          "hurst": 0.68
        }
      }
    }
    ```

## 4. 의사결정 메커니즘 (Decision-Making Flow)

1.  **(상시)** `데이터 수집 에이전트`가 데이터를 수집/저장한다.
2.  **(주기적/이벤트 기반)** `시장 국면 분석 에이전트`가 새로운 국면을 탐지하여 `메타-컨트롤러`에 보고한다.
3.  `메타-컨트롤러`는 국면 보고를 받고, 해당 국면에 맞는 전략 패러다임을 `전략 분석 에이전트`에 지시한다.
4.  `전략 분석 에이전트`는 활성화된 전략에 따라 거래 신호를 포착하여 `거래 실행 에이전트`에 전달한다.
5.  `거래 실행 에이전트`는 신호를 바탕으로 주문을 설계하고, 동시에 `리스크 관리 에이전트`에 포지션 크기 계산을 요청한다.
6.  `리스크 관리 에이전트`는 현재 포트폴리오 상태를 고려하여 최적 포지션 크기와 손절 라인을 계산하여 `거래 실행 에이전트`에 회신한다.
7.  `거래 실행 에이전트`는 모든 정보를 취합하여 최종 '거래 주문 제안'을 `메타-컨트롤러`에 보낸다.
8.  `메타-컨트롤러`는 제안을 최종 검토하고, 승인 시 `거래 실행 에이전트`에 실제 주문 집행을 명령한다.
9.  `거래 실행 에이전트`는 거래소에 주문을 전송하고, 체결 결과를 모든 관련 에이전트에게 전파한다.
